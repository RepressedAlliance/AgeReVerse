# 中文断行：保持语义，也保持原生身份

[章节文本](../chapter-texts.md) · [字体](../../../Localization-MakeGamesSpeak/Fonts-ThatFitTheGame/README.md)

## 快照与写入契约分开

`text-data/layout-baseline` 保存既定中文、实际控制字符、来源摘要及命令绑定。`binding_id` 是唯一主键；历史 `stable_id` 可能重复，不能用于盲目覆盖。日英摘要以解析后的原槽 UTF-8 字节计算，不清洗控制符或做 Unicode 归一化。没有英文槽时使用 null，控制源槽也不以听译冒充官方文本。

快照便于审阅和比较，不等于可以直接调用的 `edit_native_fields` 写入契约。目标文件变化后重绑定索引及摘要，明确允许的换行差异，不能跳过控制序列检查。后续正文、批注与姓名修正从现行 [text-data](../chapter-texts.md) 进入，不整表回退历史基线。

## 按中文语义断行

行宽包括【姓名】、引号、标点与呼号，按实际字体及界面上下文测量，再判断语义断点。JSON 的 `\n` 表示实际 U+000A，不是两个可见字符。正文不新增 U+0003；姓名括号内部不放 U+2060，但这不等于删除全文所有既有 U+2060。

姓名结构修复要保留后来审核过的断行。CString 快照只有可读内容，不能作为完整序列化字段直接替换。PUA 菜单按映射解码，并使用菜单自己的度量，不能统一套正文预算。

## 宽度告警如何处理

PF 块 `488631608` 的三个历史样本超过 724px 保守预算：

| 命令偏移／顺序 | 普通字重测量宽度 |
| --- | ---: |
| 3552／3 | 760px |
| 4316／6 | 762px |
| 8544／39 | 796px |

这些样本有整体显示良好的反馈，不能仅凭离线预算认定实机溢出。保留具体位置以便检查实际场景、回看及存档状态；不要为了消除告警擅自重排已确认句子。

## 导出已有决定

```powershell
python rUGP/tools/text/export_consolidated_review.py "<private-full-three-language.jsonl>" --games-root rUGP/games
```

导出器拒绝重复 `binding_id`、正文 U+0003、姓名内 U+2060 及与既有输出冲突的内容，保留允许公开的字段。它导出已有决定，不自动判断语义断行，也不表示新增一次全游戏人工校对。
