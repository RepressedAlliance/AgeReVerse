# PM 回顾标题与 PF 倒计时文字汉化

这组制作替换三条 CRsi 的画面文字，保持原尺寸、帧数、帧时钟和游戏音轨。
资源仍由现有 C 编解码器读写；Python 只负责排字、透视合成及流程编排。
CRsi 容器和 RUO 重定向复用现有实现，不另造一种视频格式。

| 对象 | CRsi 全局字节偏移 | 中文 | 长度 |
| --- | ---: | --- | --- |
| PM《时空的欠片》回顾，Altered Fable 源版 | 217595660 | 《时空的欠片》前情回顾 | 351 帧，30 fps |
| PM《时空的欠片》回顾，Kagayaku 源版 | 1911342516 | 同上 | 351 帧，30 fps |
| PF《告白》倒计时 | 3724567232 | 主机临界剩余时间／乘员撤离 | 51 帧，25 fps |

三条均为 1024×600。回顾两个源标题分别为 `PREVIOUSLY ON ALTERED FABLE` 和
`PREVIOUSLY ON KAGAYAKU TOKI GA KIENUMANI`。两版均按中文篇名统一标题，
原数字开场及标题动效保留；再诞技术图中保留原作英文的处理不适用于这两张篇章标题。
倒计时上栏原文为「主機臨界残時間」；下栏只露出「搭乗員退…」，原镜头裁掉了后文。
「乘员撤离」表达可见的撤离警告，不声称已经恢复画面外的完整日文。中文保持同样的镜头裁切。

## 画面制作

共用 Noto Sans SC 2.04 可变字体，身份见[字体目录](../../Localization-MakeGamesSpeak/Fonts-ThatFitTheGame/images.md)。
输入字体 SHA-256 为 `763146584cf0710223441356b4395e279021b0806c196614377a7a0174ae074a`。
制作器显式接收字体路径，输出报告记录实际散列，不依赖系统默认字体。

回顾使用 30 px、600 字重、2.5 px 字距，四倍采样后缩小。前 254 帧保持逐像素不变，
包括「2.4」数字演出；第 254–350 帧替换标题，修改范围限制在
`x=[80,945), y=[260,365)`。用每个源版本的亮字边界取得逐帧位置与缩放，
低亮度边界单独驱动光晕宽度和亮度；明显超出亮字核心的短暂残影另行重建。
两版共用文案和样式，但各自读取源动画包络。光晕与重影是重建效果，不是恢复原作者的合成图层。

倒计时先将倾斜面板变换到平面，修复无字底、排中文，再反向投影。
原画面四点 `(77,-33), (995,45), (800,831), (36,259)` 对应平面
`(0,0), (1200,0), (1200,320), (0,320)`；工作画布在平面左上各加 128 px，
避免画面边缘的旧字被误留。上栏 80 px、900 字重，下栏 190 px、900 字重，
均在投影前排字；上栏发红光，下栏沿用红底深色警告字。

无字底从可见背景拟合平滑照明，并检查独立无字底图。数字带及靠近标题的动态数字光晕受保护。
文字修复区中的轻微环境光变化按原帧保留；源像素变化超过 8 级的位置不得进入修复区。
这保留倒计时的数字变化，同时避免固定标签闪烁。遮挡背景是合理估计，不是原始像素的精确恢复。

## 离线复现

依赖沿用 [`tools/video/requirements.txt`](../tools/video/requirements.txt)，并需 FFmpeg。
这是固定场景制作器，不适用于任意同尺寸影片；字体接口要求上述单字重轴可变字体。
按[视频工具指南](../tools/video/README.md)用现有 C 解码器将指定 CRsi 输出为无损 RGB 视频，再运行：

```powershell
python -m rUGP.tools.video.story_labels recap-source.mkv recap-zh.mkv recap-composition.json --kind recap --font '<NotoSansSC-VF.ttf>'
python -m rUGP.tools.video.story_labels countdown-source.mkv countdown-zh.mkv countdown-composition.json --kind countdown --font '<NotoSansSC-VF.ttf>'
```

每次使用新的输出文件名；工具拒绝覆盖视频、报告或预览 PNG。
输出为 FFV1 无损视频、逐帧修改范围、代表 PNG，倒计时另外输出无字底 PNG。
输入须为上述对应资源；仅有相同帧数和尺寸不能证明是正确素材，须核对下述证据中的源散列。

然后使用 `encode_replacement` 和显式指定的 C codec 库生成完整 CRsi。
修改帧使用 `0x03ff` 无损编码，未修改帧及必要预测依赖由现有工具处理。
`verify_replacement` 离线模拟原生解码函数，逐帧比较 RGB 并检查帧表。
最后用 `rUGP.formats.rio.ruo.build_ruo` 将完整 CRsi 合并进现有 RUO，偏移单位为 4。

PM 候选继承已完成的《再诞》双段候选，共 32→34 条重定向；PF 候选继承原补丁，
共 21→22 条。继承的数据区与重定向须保持完全相同，新增三条资源须通过回读。
CRsi 之外的音频对象不变；MP4 只用于预览，不作为游戏资源。

## 验证范围

三条候选共 753 帧均通过原生 RGB 与帧表离线核对。PF 资源使用的是已审计的 PM
原生解码函数作为格式对照，不能称为 PF 可执行程序验证。另逐帧检查回顾文字区外像素、
前 254 帧，以及倒计时数字带内部和所有源变化超过 8 级的像素。

美术检查包含原尺寸代表图、倒计时无字底、首／中／末帧，以及两版回顾第 251–273、
318–350 帧按时间排列的源字／中文字对照。它支持对入场、短暂重影与光晕脉动的检查，
不等于完整连续视听验收。核对记录见[制作证据](../evidence/photon/video/story-labels-20261010.json)。

2026-10-12，PF 候选已在隔离 PF 游戏中沿《告白》原剧情入口实际播放。原尺寸录像中
中文标签可辨，面板透视与原镜头裁切保持，数字从 `10:00` 顺序变化至 `08:04`，
随后正常接回美知留对白。51帧／25fps 是影片本体；脚本仍会保留末帧数秒，不能把
这段停留误算为编码时长。已核对安装资源散列，普通片前档实际重载后再次到达影片，
退出后确认无 PF 进程。录像不含音频，因此不据此声称完成听校或绝对音画同步验收。
详见[PF 实机记录](../evidence/photon/video/confessions-countdown-runtime-20261012.json)。

PM 的 `1911342516` 候选已从片前普通档沿章节35原入口完整播放，捕获数字开场、
中文标题缩放与光晕，以及回到扎乌伯对白的前后边界。五个动态源帧与录像按1:1时间
推进；11.7秒影片结束后标题背景仍用于脚本对白，不能将整个约14.3秒场景窗口误算
为影片时长。另一份 `217595660` 候选通过私有测试 RUO 临时借用同一入口播放，
也完成完整边界与动态源帧核对；这证明其实际解码／显示，不证明找到了原217路线。
两次录制均无音轨，独立位移重影未在实机样本中确证，相关效果仍以离线制作检查为据。
测试后已恢复标准候选，并确认 PM／PF 均已退出。详见
[两版回顾实机记录](../evidence/photon/video/recap-runtime-20261012.json)。

四处剧情影片均已准备私有普通片前档，并实际重载到目标。存档不一定紧贴影片：
再诞开头还需推进片前剧情，结尾需等职员表，回顾可用普通快进，PF倒计时前有定时
告别演出。游戏派生视频、图片、CRsi、RUO 与个人存档只保留在私有工作目录，不随仓库发布。

下一次玩家补丁如何与其他改动合并，见[视频整合规划](../packaging/video-integration-plan.md)。
本轮验证用 RUO 不应直接替代未来发布的完整资源基底。
