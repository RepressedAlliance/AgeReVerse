# 07 · 修改反查规则

[规则顺序](README.md) · 上一步：[06 独立审核](06-review.md) · 下一步：[技术写回与 QA](workflow.md#5-技术绑定与写回)

本文规定译文、术语或理解依据发生变化后的关联检查与同步方式。目标是处理同一修改影响的其他位置，保留有语境依据的差异，避免已确认决定只落实到当前一句。

本文适用于初译、独立审核、疑点定稿、维护者修改和玩家反馈处理，不只在章节结束时执行。初译与审核分别遵守 05、06；资源写回和技术验证遵守对应引擎规则。

## 1. 反查边界

1. 只修改当前明确指定的游戏、章节和目标语言。
2. 可以在可访问的项目资料中查找必要关联；范围外需要修改的位置应记录并交接，不直接改动其他章节正文。
3. 反查以当前版本 JP、实际上下文和当前采用决定为依据，不能用旧中文反向决定原意。
4. 搜索命中用于发现候选，不代表这些位置都应采用相同译法。
5. 已判定 `keep`、已经定稿或采用旧译文的条目，同样可能需要复核。
6. 反查不默认写回游戏资源、打包或发布。

## 2. 什么时候反查

出现以下情况时，应判断影响范围并开展相关检查：

- 人名、昵称、称谓、术语或固定表达的译法及适用条件发生变化。
- 新证据改变了人物关系、指代、剧情含义或场景衔接的判断。
- 疑点得到解决，或修改建议被确认采用。
- 发现可能重复出现的误译、漏译或表达问题。
- 原文版本、场景对应或其他审核依据发生变化。
- 技术、实机或玩家反馈导致已采用文本再次修改。

修改范围按实际影响确定。局部错字或病句可以只复核当前句与必要上下文；涉及共用译法或理解依据时，应检查相关出现位置。多个修改可以合并反查，但应能对应到各自决定。

## 3. 确认输入与当前文本

开始反查前，应明确：

1. 本次游戏、章节、目标语言及可修改范围。
2. 修改涉及的稳定身份、源版本和必要上下文。
3. 旧译与新译，或变化前后的判断与适用条件。
4. 修改原因、采用决定和当前术语基线。
5. 当前生效正文及尚未并入正文的已采用记录。

已有审核、术语和定稿记录可以直接复用，不要求重复建立一套表。存在互相冲突的采用记录时，先确认当前决定，不能按文件顺序任意覆盖。

发现源哈希或资源身份漂移时，按 02 停止写回并重新核验。

## 4. 查找受影响位置

根据修改内容，检查以下相关范围：

1. 相同 JP 及已知别名、写法变体。
2. 旧中文、新中文和已有译法变体。
3. 同一对象的称呼、指代和语境限制。
4. 同一段话的拆分记录、铺垫、回应和重复引用。
5. 共用文本、相关分支及其他受同一决定影响的位置。
6. 依赖旧判断的术语说明和审核记录。

检查对象使用当前有效译文，不以历史候选代替正文。不能只检索旧中文，也不能只检查尚未处理的条目。

记录实际检索范围和相关位置。检索结果被截断、源资料不全或关联范围无法确认时，应说明限制，不能以部分结果代表完整覆盖。

## 5. 逐项判断与同步

对相关位置分别判断：

- 需要修改：说明与本次决定的关系，给出完整新译文。
- 已经符合：确认当前文本无需改动。
- 保留差异：说明人物、场景、义项或表达功能上的区别。
- 尚未解决：记录具体问题、缺少的依据和后续处理条件。

同一 JP 不一定需要相同中文；同一中文也不一定对应同一对象。不得为了表面一致而消除有依据的称谓、语气或语义差异。

已确认采用的修改应同步到当前工作正文或其明确关联的生效记录，并更新确实受影响的术语基线、审核说明和统计。历史记录保留原有事实，但不能继续作为当前决定使用。

公共术语同步遵守 04。范围外位置交由对应维护者处理。

采用某种译法，不等于相关考据已经证实。疑似原文错误、未证实的梗和按上下文采取的处理，应保留事实与采用决定之间的区别。

## 6. 修改后复核

1. 按 06 的相关维度重新检查修改后的完整译文。
2. 回读必要上下文，确认指代、称谓、铺垫与回应仍然成立。
3. 核对关联位置和相关记录是否落实了同一采用决定。
4. 修改涉及符号、编码、容量或资源绑定时，执行对应引擎的相关检查。
5. 复核发现新的受影响位置时，继续查找并处理。

检查深度应与修改影响相匹配。不规定固定复查轮数，也不因一次局部修改重新审核无关文本。输入、规则和工具未发生相关变化时，可以复用已有结果；只在相关失败、新证据、依赖变化或明确交付要求下扩大或重复检查。

程序检查没有报警，不等于语义与关联位置已经全部通过。

## 7. 反查输出

每次或每批至少保留：

1. 修改依据：旧译、新译或规则变化，以及原因和采用记录。
2. 检查范围：实际检查的数据、检索线索和必要上下文。
3. 处理结果：相关稳定身份、修改或保留结论及必要理由。
4. 未完成事项：待确认问题、范围外位置和资料限制。
5. 当前结果：哪些已经同步，哪些仍为建议，以及相关检查结果。

输出可以并入已有章节工作记录。完整 JP、临时讨论和个人路径的公开边界遵守 02，不默认加入公开补丁源表。

## 8. 完成标准

声明范围内的修改反查完成时，应满足：

1. 本次采用决定及其适用范围明确。
2. 已识别的相关位置均有处理结论。
3. 应修改的位置已经落实，保留差异有依据。
4. 受影响的正文、术语和审核记录没有未说明的冲突。
5. 没有尚待处理的新线索，相关复核与技术检查已经完成。
6. 实际完成范围与交接说明一致。

仍有待确认或待同步位置时，应标明未完成范围，不能将其计为全部完成。范围外事项可以交接，但不能据此宣称全项目已经一致。

相关检查通过且没有未解决问题后停止。反查完成不等于资源已写回、补丁已更新或实机 QA 已通过。
